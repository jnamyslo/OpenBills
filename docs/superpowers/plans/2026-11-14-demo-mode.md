# Demo-Modus + konfigurierbare Passwort-Mindestlänge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (a) Passwort-Mindestlänge per `PASSWORD_MIN_LENGTH` einstellbar. (b) `OPENBILLS_DEMO=true` macht eine Instanz zur öffentlichen, abgeriegelten Demo mit Demo-Login, Mail-Abfang, Sperrliste und 3-stündlichem Reset auf datums-relative Demo-Daten.

**Architecture:** Neues Backend-Modul `backend/demo/` (Flag, Konstanten, Guard-Middleware, Schutzprüfung, Reset, Seed). Mail-Abfang an den zwei Transport-Fabriken. Öffentliche Endpoints `GET /api/auth/password-policy` und `GET /api/demo` liefern dem Frontend Mindestlänge bzw. Demo-Infos.

**Tech Stack:** Express (ES Modules), pg, nodemailer, Vitest + supertest, React/TS.

**Spec:** `docs/superpowers/specs/2026-11-14-demo-mode-design.md`. Passwortlänge: keine eigene Spec – Entscheidung im Gespräch (Nutzerwunsch; Untergrenze 8 eigene Entscheidung): Env `PASSWORD_MIN_LENGTH`, Default 12, erlaubt 8–128, ungültig → Startfehler.

## Global Constraints

- Ohne `OPENBILLS_DEMO=true` und ohne `PASSWORD_MIN_LENGTH` verhält sich alles exakt wie heute.
- Demo-Zugang: `demo@openbills.de` / `demo`, Rolle `admin`, `is_operator=false`, kein 2FA. Demo-User wird direkt angelegt (umgeht `validatePassword`).
- Gesperrte Aktion → `403 { error: 'In der Demo deaktiviert', code: 'DEMO_DISABLED' }`.
- Schutz-Startfehler exakt: `Datenbank enthält echte Daten – Demo-Modus verweigert`.
- Demo + nicht-leeres `OPENBILLS_PLAN` → Startfehler `OPENBILLS_DEMO und OPENBILLS_PLAN schließen sich aus`.
- Reset zu jeder vollen Stunde, die durch 3 teilbar ist (Container-TZ), plus beim Start.
- Backend ES Modules mit `.js`-Imports. UI-Text Deutsch. Strict TS.
- **BTEST** / **FTEST** wie in `docs/superpowers/plans/2026-11-13-auth.md` („Testlauf“): Postgres-Container `obtest-db`, Backend-Tests mit `DB_HOST=obtest-db …`; DB-Tests `describe.skipIf(!hasDb)`.

## Review Focus

1. **`OPENBILLS_DEMO=true` auf Instanz mit echten Daten** → Start bricht ab, keine Zeile gelöscht, `backups/` unangetastet. Test in Task 4.
2. **Besucher tippt 10× falsches Passwort für `demo@openbills.de`** → kein Account-Lock, Demo-Login danach sofort möglich. Test in Task 3.
3. **Mail an echte Adresse über jeden Pfad** (Rechnung, Angebot, Mahnung, Einladung, PW-Reset, Plattform-Relay) → kein SMTP-Verbindungsaufbau. Test in Task 3 (beide Transport-Fabriken liefern jsonTransport).
4. **Reset während ein Besucher gerade speichert** → Request schlägt mit 401 fehl, Frontend zeigt Login (bestehendes Verhalten); Reset-Transaktion selbst atomar. Test in Task 4 (Reset in Transaktion, Fehler → Rollback, Marker bleibt).
5. **Reset-Zeitpunkt kurz vor Mitternacht / exakt auf 3:00:00** → nächster Reset korrekt (21:59 → 00:00 Folgetag; 03:00:00 → 06:00). Test in Task 4.
